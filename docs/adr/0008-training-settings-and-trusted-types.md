# ADR 8: Training settings and trusted model types
Status: accepted
Context: The training step trains the baseline and needs fixed settings that training, tuning, evaluation and serving all read. config.py is a shared file, so adding to it needs an ADR and approval. The random forest is saved in the safe model format (skops), which refuses types it does not know unless the project lists them.
Decision:
1. config.py gets constants for values already fixed by the brief, docs/tuning-plan.md and ADR 7: label horizon and embargo (60 minutes), the scope bounds of ADR 7, the split dates, the sample size (300000) and seed (42), the fold table, the result file paths including LOCK_PATH, the post-trip column list of ADR 2, the feature list, the model name, and the model size limit of the tuning plan (300 MB, counted as 300,000,000 bytes). No value is new. Changing one later needs a new ADR and a new locked baseline.
2. Features: trip_distance, pickup hour, pickup day of week, pickup zone id, dropoff zone id. Zone ids are encoded by an ordinal encoder inside the model pipeline, fitted on each training fold only, with unseen zones mapped to -1. Date and day of month are not features, because the test week has dates the model never saw.
3. The baseline model is saved once locally, only to measure the real skops file size. The run is logged to the model store with parameters, per-fold scores and the measured size, but without the model artifact. A model is registered as taxi-duration with alias baseline only if its file is under the 300 MB limit of the tuning plan. The reason is the file size, not the score. The alias champion is set in the tuning step, on the model the decision rule picks after the size and speed limits are checked. The API serves champion only.
4. The lock records the source file SHA-256 (from the data record), a SHA-256 of the sorted trip keys of the sample, and per fold the train and valid row counts plus a SHA-256 of that fold's sorted trip keys. reports/results/cv_folds.json (26 MB) is git-ignored: it is rebuilt from the seed, and these hashes check the rebuild.
5. Trusted types: the allow list is the environment setting MODEL_TRUSTED_TYPES (.env.example). It holds only sklearn.tree._tree.Tree, which the random forest needs. If skops reports another untrusted type for this model, work stops and a new entry needs its own ADR. Never trust all types, and never use the list the model file carries.
6. Free disk space is checked before any model file is saved, and the saved file size is reported.
7. The CLI is added with the training step (ADR 5): train and evaluate. Evaluate reads no test rows here; the test week option comes with the tuning and evaluation step.
8. Training fits the forest with n_jobs=-1 for speed. With a fixed random_state this gives the same fitted trees as n_jobs=1 and changes only the run time. Before the model is saved, and before any prediction-speed measurement, n_jobs is set to 1 on the fitted model, because the API predicts single rows.
9. Behavioral cases (tests/behavioral/cases.toml, three cases: one minimum functionality, two directional) were approved by jolennd on 2026-11-17. Agents do not change them. The kit template is classification-shaped; the project copy compares predicted minutes (see the test file).
10. Behavioral tests (minimum functionality, invariance and direction cases on the saved model) are deferred to the tuning step. They run there on the model that passes the size limit and is the one the API serves. They are not run on the 2.7 GB baseline, which is not registered (point 3). The approved cases stay as they are; the regression version of the test files (expected_min, predicted minutes) is written in that step.
11. The registry verify files (verify_model.py and its tests, from the model store variant) are not copied in the training step, because no model is registered and nothing loads one yet (point 3). They are copied in the tuning step, with the model that passes the size limit. When they are copied, the end-to-end test must create its experiment with an artifact location inside tmp_path, because logging to a temporary sqlite store without a server writes artifacts to ./mlruns in the current folder.
12. config.py also gets MAX_PREDICT_MS = 50, the prediction time limit of docs/tuning-plan.md (one single-row prediction under 50 ms), next to MODEL_SIZE_LIMIT_BYTES. No value is new. Approved by jolennd on 2026-11-18.
13. Clarification of docs/tuning-plan.md, not a change: in the fallback for a candidate that fails the limits, the max_depth caps are tried in the plan's order, but a cap at or above the candidate's own max_depth is skipped, because it would retrain an identical model. A candidate with no max_depth limit skips no cap. The skipped caps are recorded in the results. Approved by jolennd on 2026-11-18.
14. When tune.choose_final returns None (no candidate passes the limits), run_tuning applies the plan's fallback automatically (depth caps, then halving, with caps skipped by point 13), scores each capped model on the 3 folds, writes the fallback result to trials.json, and then stops and reports to the human. Nothing is registered by run_tuning in any case; registration is the separate register command, run by the human after reading the report. If the fallback finds no model that passes, run_tuning stops and reports the same way, and nothing is registered. When tune.first_passing_after_retrain returns None, work stops and is reported to the human. Skipped caps are recorded only when the fallback ran. Approved by jolennd on 2026-11-18 (revised from the first version of this point).
15. The baseline is never saved again. Its measured skops file size is 2,694,430,930 bytes (training step), and the tuning step uses that number as the baseline size without saving the model. Its prediction time is measured in memory with n_jobs=1, on the fold 3 refit. Approved by jolennd on 2026-11-18.
16. The baseline is not registered (point 3), so the test week scores it from an in-memory refit: the same sample and seed from the lock. Before fitting, the sample's trip key hash must equal sample_sha256 in baseline_lock.json, or evaluation stops. No baseline file is saved or loaded, and the BASELINE_MODEL_URI and BASELINE_MODEL_SHA256 settings are not used. Approved by jolennd on 2026-11-18.
17. A fallback model (point 14) is registered only by the human running `register --approved-fallback` after reading the tune report. Running it is the approval. Plain `register` still refuses when the fallback ran, and `--approved-fallback` refuses when it did not. Approved by jolennd on 2026-11-18.
18. The test week is read once, and the attempt is recorded. Before it calls load_test, evaluation writes reports/results/test_read_started.json. If that marker exists without metrics.json, evaluation refuses to run, because an earlier attempt may have read the test week and failed before writing the results. Removing the marker is a human decision and needs an ADR that says the test week was read more than once. Approved by jolennd on 2026-11-18.
19. MLflow settings are strict. Tuning, registration, evaluation and the verify step accept only the tracking address http://127.0.0.1:5001 (scheme http, host 127.0.0.1, port 5001, no user info). The model URI is exactly models:/taxi-duration@champion, and the version is read once from the alias, so the downloaded version is the one recorded. For this, the project copy of verify_model.py now differs from the kit file: it adds check_strict_tracking_uri (the address check above), a version argument on verify_then_load that pins the download to the version read once from the alias (so a moved alias cannot change which model is loaded), and a refusal in main when MLFLOW_TRACKING_URI is unset (the kit file defaults to port 5000, which this project does not use, and settings come only from the environment). Everything else is the kit file. Contract tests of the variant (tests/integration/test_verify_model.py) pass, with one test edited (see point 20). The same strict check also applies where train.py reads MLFLOW_TRACKING_URI from the environment (baseline logging). A trial whose model file cannot be saved because of disk space (check_disk) counts as failing the size limit and does not abort the study. Approved by jolennd on 2026-11-18.
20. The pinned hash is one value for every load path. MLflow writes a client-side file (registered_model_meta) into every folder downloaded from models:/, and its text differs between a download through the alias and a download pinned to a version. So every path (register_champion, verify_model.main, evaluation, and serving later) does one alias lookup and then a download pinned to that version, and the hash is computed on that download. The shared hash function and the rule that it covers every file stay unchanged. Because that file holds the version number, the pin includes the version and moves with each promotion, together with the alias (core/model-loading.md rule 3). One kit contract test changed because of this: test_verify_then_load_by_alias_end_to_end in tests/integration/test_verify_model.py took its pin from an alias download, which no longer matches the version-pinned download that verify_then_load now makes. It now takes the pin from a version-pinned download. The check stays as strict: the pin must equal the hash of the files that are loaded. The project test test_registers_the_exact_skops_file_and_pins_the_folder_hash in tests/integration/test_register_champion.py changed the same way. Approved by jolennd on 2026-11-18.
21. In the retrain and in the fallback, a save or disk error (artifacts.check_disk and save_model) counts as a failed size limit for that attempt, as it does for a trial, and never crashes run_tuning. The idempotent re-register path re-runs check_model_metadata before it returns the existing version. Approved by jolennd on 2026-11-18.
Consequences: One place for each number, so a test can compare plan and code. A model needing another type is blocked until the human approves it. The forest's skops file may be large; the size is measured and reported, and the 300 MB limit of the tuning plan applies in the tuning step.
