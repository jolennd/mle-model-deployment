# ADR 2: Serving-time features
Status: accepted
Context: The model is trained on trip_distance, which the data dictionary defines as the elapsed distance reported by the taximeter, so it is known only after the trip. It is also trained on the actual dropoff zone. At request time neither value is measured, so the API cannot supply the same quantities that training used.
Decision: The API takes four inputs: the pickup zone, the dropoff zone (the destination the passenger states at pickup, as in a street hail or a booking), the trip distance (a route estimate supplied by the caller) and the pickup time. The exact model features are decided when the model is built. Post-trip columns are never used as features: fare_amount, tip_amount, tolls_amount, total_amount, payment_type, RatecodeID, extra, congestion_surcharge, Airport_fee, cbd_congestion_fee. Code that enforces this list compares column names case-insensitively.
Consequences: The reported RMSE is optimistic for real requests, because training used measured distances and real requests carry estimates. The README says so next to the RMSE. A robustness check that scores the test week with noisy distances is future work and is not part of the current plan. The caller is responsible for the quality of the distance estimate and for a valid destination.
